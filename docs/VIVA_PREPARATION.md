# VIVA PREPARATION (SENTINEL)

## Core Concepts

### Search Algorithms
1. **BFS** - Finds path with fewest edges using a queue (FIFO). Neighbours explored alphabetically for determinism. Visited prevents revisiting.
2. **DFS** - Depth-first exploration with alphabetical neighbour order. Recursive with visited set; in our implementation follows A->B->D->C->E->F for the assignment graph (cost 13, risk 19) as per DOCX correction.
3. **UCS (Uniform-Cost Search)** - Dijkstra's algorithm minimising total travel cost. Uses heapq keyed by cumulative cost; skips stale heap entries.
4. **Risk-aware search** - Dijkstra minimising J(P)=∑c(e) + λ·∑r(e), λ=1. Costs and risks non-negative so Dijkstra is correct. May differ from UCS.
5. **Why shortest route not safest?** Fewer edges/lower cost can traverse higher-risk edges (e.g. A->B is cheap in structure but high risk).

### Agent & PEAS
6. **PEAS** - Performance measure (accuracy, response time, unnecessary rejections), Environment (campus graph, users, transactions, incidents), Actuators (ALLOW/REJECT/INVESTIGATE/ESCALATE), Sensors (logs, auth, risk, alerts).
7. **Policy priority** - RULE_1 confirmed_compromise->ESCALATE, RULE_2 critical_alert->ESCALATE, RULE_3 authorized AND risk<=2->ALLOW, RULE_4 duplicate_conflict->INVESTIGATE, RULE_5 risk>=7->REJECT, RULE_6 default INVESTIGATE. Order is mandatory.
8. **Why priority matters** - I03: authorized+low risk but confirmed compromise must escalate.

### Machine Learning
9. **Features** - failed_logins, requests_per_min, unusual_hour, known_device, duplicate_count. Label (NORMAL/SUSPICIOUS/CRITICAL) is target only.
10. **No data leakage** - Label never in features; split before/independent; only training data used to fit.
11. **Stratified split** - Preserves class proportions in train/test.
12. **Metrics** - Accuracy overall; Precision/Recall/F1 macro-averaged (treat all classes equally). Confusion matrix shows TP/FP/FN.
13. **Synthetic data limitations** - Generated by rules; high accuracy doesn't prove real attack detection. Overlap between classes prevents perfect classification.

### Integration & Robustness
14. **Separation of responsibilities** - ML predicts class, agent chooses action. Policy authoritative.
15. **process_incident** - Validates, predicts, applies rules, computes route if requested, returns JSON-compatible result.
16. **Robustness cases** - Missing risk (error), unknown node (error), negative cost (rejected), contradictory fields (detected), duplicate IDs (rejected/no merge), prompt injection (untrusted, policy unchanged).
17. **Live modification** - Change edge weights in graph and rerun searches; results recomputed dynamically.
